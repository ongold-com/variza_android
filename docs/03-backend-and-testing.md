# ۳) فرمت درخواست بک‌اند و روش تست

## درخواستی که اپ می‌فرسته
```
POST <آدرسی که توی اپ وارد کردی>
Content-Type: application/json
X-API-Key: <مقدار Secret به نام API_KEY>     ← اسم هدر با API_KEY_HEADER قابل تغییره

{
  "from": "+989121234567",
  "body": "متن دقیق پیامک",
  "receivedAt": 1732270000000,
  "simSlot": 0,
  "subscriptionId": 1
}
```
- `receivedAt`: زمان دریافت به میلی‌ثانیه (Unix).
- `simSlot`: اسلات سیم‌کارت از ۰ (اگه گوشی ندهد `-1`).
- پیام تست (دکمه‌ی «تست اتصال») با `"from": "TEST"` فرستاده می‌شه.
- بک‌اند باید **کد 2xx** برگردونه. هر چیز دیگه یعنی خطا و اپ **هر ۱۰ ثانیه** دوباره می‌فرسته. پس بک‌اند باید مقاوم به پیام تکراری باشه (مثلاً با `from + receivedAt + body`).

## تست سریع بدون بک‌اند
1. برو به https://webhook.site و آدرس یکتا رو کپی کن.
2. توی اپ بذارش به‌عنوان آدرس بک‌اند و **تست اتصال** بزن؛ باید درخواست با هدر API Key و JSON اونجا ببینی.

## سناریوهای تست
| تست | نتیجه‌ی درست |
|---|---|
| شماره‌ای رو اضافه کن و از اون شماره پیامک بفرست | به بک‌اند می‌رسه و «✓ ارسال شد» می‌شه |
| از شماره‌ای که توی لیست نیست پیامک بفرست | هیچ اتفاقی نمی‌افته و ذخیره هم نمی‌شه |
| اینترنت گوشی رو قطع کن و پیامک بفرست | «⟳ تلاش مجدد»؛ با وصل شدن اینترنت ≤ ۱۰ ثانیه می‌ره |
| بک‌اند خطا بده (مثلاً 500) | تلاش مجدد هر ۱۰ ثانیه |
| اپ رو از Recent apps ببند و پیامک بفرست | باز هم فوروارد می‌شه |
| گوشی رو ری‌استارت کن (بدون باز کردن اپ) و پیامک بفرست | فوروارد می‌شه (بعد از بوت ممکنه چند ثانیه طول بکشه) |
| به هر دو سیم‌کارت پیامک بفرست | هر دو فوروارد می‌شن |
